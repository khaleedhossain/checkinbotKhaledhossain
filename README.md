# Scheduled Check-In Bot

## Overview

This project implements an automated bot that runs on a GitHub Actions schedule to interact with the Practice Hub REST API. The bot performs two main tasks:

1. **Collect Posts** - Fetches all instructor posts with full content and downloads all attachments
2. **Reply to Check-ins** - Automatically replies to check-in posts within their open windows

The bot runs daily and commits its collected data to the repository as an artifact for review.

## Features

- **Automatic Scheduling**: Runs daily via GitHub Actions cron schedule (10:00 AM UTC)
- **Manual Trigger**: Can be run manually via `workflow_dispatch`
- **Full Post Collection**: Retrieves complete post bodies (not truncated previews)
- **Attachment Download**: Automatically downloads all files attached to posts
- **Pagination Support**: Handles API pagination to collect all instructor posts
- **Check-in Detection**: Identifies check-in posts by keyword matching in title
- **Duplicate Prevention**: Checks existing comments to avoid duplicate replies
- **Error Handling**: Gracefully handles closed check-in windows (423 responses)
- **Secure Credentials**: Uses GitHub Secrets for API token storage


### 2. Install Dependencies


### 3. Configure GitHub Secrets and Variables

Go to **Settings → Secrets and variables → Actions** and add:

#### Secrets (keep private):
- **PRACTICE_API_TOKEN**: Your Practice Hub API token
- **PRACTICE_API_URL**: `https://practice.fhsucyber.com`

#### Variables (public):
- **INSTRUCTOR_ID**: `7` (instructor's user ID)

Example in `.github/workflows/checkin.yml`:
```yaml

  PRACTICE_API_TOKEN: ${{ secrets.PRACTICE_API_TOKEN }}
  PRACTICE_API_URL: ${{ secrets.PRACTICE_API_URL }}
  INSTRUCTOR_ID: ${{ vars.INSTRUCTOR_ID }}
```

## Running the Bot

### Automated (Default)

The bot runs automatically every day at **10:00 AM UTC** via GitHub Actions.

To adjust the schedule, edit `.github/workflows/checkin.yml`:
```yaml
schedule:
  - cron: '0 10 * * *'  # Change this cron expression
```

### Manual Trigger

Run the bot manually from the GitHub Actions tab:
1. Go to your repository
2. Click **Actions** tab
3. Select **Scheduled Check-In Bot**
4. Click **Run workflow** → **Run workflow**

## How It Works

### Task 1: Collect Posts

1. Connects to Practice Hub API using authentication token
2. Fetches all posts by the instructor (ID: 7)
3. For each post:
   - Retrieves full post details (complete body, not preview)
   - Downloads all attached files to `artifact/files/`
   - Stores metadata (title, body, tags, timestamps)
4. Handles pagination automatically
5. Saves all data to `artifact/collected.json`

### Task 2: Reply to Check-ins

1. Scans collected posts for "check-in" keyword in title
2. For each check-in post:
   - Checks if already replied (to avoid duplicates)
   - Posts a reply comment if window is open
   - Handles 423 (Locked) response gracefully if window closed
3. Logs success/failure for each reply

## API Endpoints Used

- `GET /api/v1/datasets/posts` - Fetch posts with pagination
- `GET /api/v1/datasets/posts/{id}` - Get full post details
- `GET /api/v1/datasets/posts/{id}/comments` - Check existing comments
- `POST /api/v1/datasets/posts/{id}/comments` - Reply to post
- File download via attachment URLs

## Error Handling

| Error | Handling |
|-------|----------|
| **423 Locked** | Check-in window closed; logged but not retried |
| **Network Error** | Logged; bot continues with other posts |
| **Missing Token** | Bot exits with error message |
| **API Rate Limit** | Requests library handles with exponential backoff |
| **Duplicate Reply** | Skipped; checks existing comments first |

## Troubleshooting

### No artifacts generated
- Check if PRACTICE_API_TOKEN secret is set correctly
- Verify INSTRUCTOR_ID is correct (should be 7)
- Check GitHub Actions logs for API errors

### Bot not replying to check-ins
- Ensure check-in window is still open (923 errors indicate window closed)
- Verify keyword "check-in" is in post title (case-insensitive)
- Check if already replied (duplicate prevention)

### Files not downloaded
- Verify file URLs are valid in API response
- Check API token has permissions for attachment download
- Ensure `artifact/files/` directory has write permissions
